# ADR-0001：干净核心与来源适配器

- 状态：Accepted
- 日期：2026-08-10

## 背景

`daily_stock_analysis` 具备成熟的日常分析产品体验，但其权威领域模型围绕当前行情、报告和 LLM 分析；用户原项目具备 PIT、版本和量化治理合同，但主线偏港股 current-only，且产品复杂度已经较高。直接以任一仓库作为运行时核心，都会继承与 A 股严格基本面量化目标冲突的边界。

## 决策

新平台建立独立、框架无关的领域核心。两个来源仓库保持只读，通过以下方式吸收：

1. 先在新核心定义目标合同；
2. 为来源能力建立 adapter 或经过 provenance 记录的迁移模块；
3. 不允许新核心 import 来源仓库内部包；
4. DSA 的 UI、Agent、报告和通知在核心稳定后接入应用层；
5. Legacy 的 PIT、版本、信号、组合和回测思想优先进入领域层；
6. 所有第三方代码迁移前先确认许可证。

## 结果

优点：

- 避免两个大型代码库永久耦合；
- 可以保留 DSA 产品体验，又不把其报告评估误当策略回测；
- 可以保留 legacy 的严谨合同，又不复制港股偏置和过多尚未闭环模块；
- 每次迁移都有可测试的目标语义。

代价：

- 初期需要重写 adapter 和部分领域对象；
- DSA Web 不能立即直接运行在新核心上；
- 必须维护清晰的迁移清单和 provenance。

## 被否决方案

- 直接 fork DSA 并在其 SQLite schema 上追加 PIT：当前报告领域和严格历史数据语义耦合过深；
- 直接继续 legacy：A 股黄金链路和日常产品体验仍不清晰；
- 将两个仓库作为依赖同时 import：版本、领域对象和数据权威会长期冲突。
